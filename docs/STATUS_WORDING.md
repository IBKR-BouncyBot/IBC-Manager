# Status presentation in 2.0.3

This release changes display text only. Diagnostic RuntimeState enum values, state
precedence, process/listener ownership checks, warning colours, command guards and
recovery timers are unchanged. The normal green state does not assert bot/account
verification and does not add any active API connection.

| Diagnostic state | Main status headline |
|---|---|
| API_LISTENER_DETECTED | Gateway running - API listener available |
| RUNNING | Logged in - API listener unavailable |
| WAITING_FOR_LOGIN | Waiting for Gateway login |
| WAITING_FOR_SECOND_FACTOR | Waiting for 2FA approval |
| VALIDATING | Checking profile |
| STARTING | Starting Gateway |
| RESTARTING | Restarting Gateway |
| STARTING_FRESH | Starting a new Gateway session |
| AUTO_RECOVERY_STOPPING | Recovering - stopping Gateway |
| AUTO_RECOVERY_FORCE_CLEANUP | Recovering - clearing stalled processes |
| AUTO_RECOVERY_COOLDOWN | Recovering - waiting to restart |
| STARTUP_STALLED | Gateway startup stalled |
| RECOVERY_FAILED | Automatic recovery failed |
| PAUSING / PAUSED | Pausing Gateway / Gateway paused |
| STOPPING / STOPPED | Stopping Gateway / Gateway stopped |
| ERROR | Action required |
| UNKNOWN | Checking Gateway status |

If login is complete but listener inspection is unavailable, the headline is
"Logged in - checking API listener" rather than claiming the port is absent.

The sidebar and Overview Status row use compact versions of these labels. Hover over
Status for its unchanged diagnostic code. Specific errors are still displayed in
Details; friendly labels do not hide failure evidence. The two-line sidebar escapes
user-controlled profile names as text rather than interpreting them as HTML.

The bottom activity bar says "Startup requested" or "Stop requested" after a
normal action; it does not announce completed login or completed shutdown before
the runtime state confirms it. Force Stop success is reported separately.

The API row and green indicator retain an on-demand explanation: Manager monitors
Gateway and its API listener without opening an API connection; the trading client
verifies its own API connection, account and permissions. The permanent Overview
footer has been removed, not replaced with another always-visible disclaimer.

The success detail states listener availability and observed address/PID. An unrelated
or unverifiable listener retains its caution state and ownership message. Failed
listener inspection is not relabelled as a successful connection.

## README screenshot

images/GUI.png is generated by the real Manager GUI smoke runner with a labelled
synthetic paper-profile fixture. It is not a photograph of a live trading session.
The fixture is test-only and never included in the production JAR. GUI appearance
on Windows can differ from the Linux/Xvfb capture because native Swing themes differ.

After compilation, run `BuildProject.java gui-screenshot` on an interactive display
(or under Xvfb on a development host). The gate runs the real GUI assertions and
writes build/GUI.png without touching the checked-in image. Review it before copying
to images/GUI.png. Rebuild the distribution after changing the checked-in image.
